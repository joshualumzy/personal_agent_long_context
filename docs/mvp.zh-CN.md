# 个人上下文智能体 MVP

[English](./mvp.md) | [简体中文](./mvp.zh-CN.md)

本文档是当前课程项目和黑客松 MVP 的简体中文版本。英文版 [`docs/mvp.md`](./mvp.md) 是最终权威版本；如两者存在差异，以英文版为准。`docs/research/` 下的研究笔记探讨了更完整的生产方案。当这些笔记建议的基础设施超出本文档的范围时，MVP 以本文档为准。

## 目标

证明个人智能体能够接收用户主动提交的文字记录，长期保留有用的上下文，处理用户后来提出的更新或取消，并根据用户当前有效的信息回答问题，而不会重新使用已经过时的信息。

同一个产品支持两套不同的提交叙事：

- **IT5007：** 一个可运行的全栈应用，包含有实际意义的后端集成、测试、文档和评估。
- **Show Me Your Agents：** 一个与 SME 场景相关的个人上下文工作流，具备明确的记忆能力、安全边界、可检查性和可量化的结果。

## 架构

```text
前端
  |
轻量服务端适配层
  |
部署在 AWS 上的自托管 Letta App Server
  |
已配置的模型提供商
```

在 MVP 中，持久化记忆由 Letta 管理。除非评估发现了明确且与产品相关的问题，否则应用不会额外实现独立的权威记忆数据库、类型化记忆状态机、删除账本或与供应商无关的记忆服务。

轻量适配层只负责应用边界所必需的工作：

- 避免浏览器直接接触凭证和 Letta 管理接口；
- 接收包含 `user_id`、`recorded_at` 和来源标识符的文字记录；
- 执行同意声明和基础的禁止数据检查；
- 将每个请求发送给正确的 Letta 智能体；
- 提供文字记录导入、提问、记忆检查和评估追踪接口。

开发和评估阶段可以使用本地 Letta。AWS 部署属于交付工作，不会改变产品边界。

## 用户流程

1. 演示用户确认同意声明，并提交一份带日期的文字记录。
2. 适配层拒绝明显的禁止数据，并将通过检查的文字记录发送给该用户的 Letta 智能体。
3. 用户可以查看 Letta 保留的上下文，并针对这些上下文提问。
4. 用户之后提交的文字记录可以更新或取消先前的信息。
5. 智能体使用当前有效的信息回答，并排除已被取代的信息。

MVP 优先支持文字记录。音频上传和语音转写属于记忆工作流端到端运行之后的扩展目标。

## 评估门槛

Memora 是原生 Letta 记忆的第一个评估标准，而不是产品界面。

1. 构建最小可用的 Letta 导入和查询适配层。
2. 运行约 15–25 个高频更新的 Memora 问题，覆盖信息更新、取消、长历史和过时信息排除。
3. 不向智能体输入基准测试中的操作标签、预期答案或评分证据。
4. 报告适用的 Memora 信息存在与遗忘相关分数，以及明显的延迟或成本限制。
5. 如果结果足以支持演示，则继续使用 Letta 管理记忆。只有在反复出现且与产品有关的问题确实需要解决时，才研究由应用管理的记忆方案。

完整运行一个每周人物数据集、全部 600 个问题、多种 Letta 记忆配置、音频评估和额外基线，都属于可选扩展，而不是 MVP 的完成门槛。

## 范围内

- 一个演示用户，且每个请求都包含 `user_id`；
- 用户主动提交的合成、经过参与者同意的演示，或第一方文字记录；
- Letta 原生持久化记忆；
- 后续更新和取消；
- 提问和记忆检查；
- 同意声明和基础的禁止数据过滤；
- 一小组明确说明范围的 Memora 评估样本；
- 足以解释系统行为的追踪记录和截图。

## 暂缓实现

- 与 Recording Necklace 直接同步；
- 持续监听、隐蔽录音、环境录音或说话者身份未知的录音；
- 生产级多用户认证、管理或共享；
- 自定义记忆数据库或显式记忆状态机；
- 针对每条记忆的批准、编辑和拒绝流程；
- 全面的 PII 分类、敏感记忆保险库或经过验证的级联删除；
- 生产级隐私、备份、事故响应和跨境数据治理控制；
- 完整复现 Memora 或进行大规模配置扫描；
- 音频转写和 ASR 评估，除非核心文字记录工作流已经完成。

## 声明边界

MVP 可以声称：它展示了用户主动提交的多份文字记录之间的上下文连续性，并评估原生 Letta 记忆能否处理后续更新和取消。

MVP 不得声称：它已经达到生产级隐私合规、能够在所有系统中安全彻底删除数据、能够可靠处理环境录音，或已经验证完整的消费级产品。
